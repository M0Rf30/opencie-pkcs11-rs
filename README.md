# opencie-pkcs11

Rust bindings for [libopencie-pkcs11](https://github.com/M0Rf30/opencie-pkcs11) — the PKCS#11 interface for the Italian CIE (Carta d'Identità Elettronica).

The crate exposes:

- **PKCS#11 standard interface** — the full Cryptoki C API generated by `bindgen`, plus safe Rust wrappers for the common session/sign/encrypt/decrypt operations.
- **CIE extensions** — `cie_enable`, `cie_disable`, PIN management, PDF signing, signature verification, certificate retrieval, RFC 3161 timestamps, ICAO 9303 chip data-group reading (CAN or PIN based), reader watching, error classification and the DigestInfo helper, all wrapped in idiomatic Rust.

The standalone `cie_sign_*` C++ Sign SDK is no longer exported from the C library and has been removed from these bindings (see [Changelog](#changelog)). PDF signing now goes through `cie::sign`.

## Installation

```toml
[dependencies]
opencie-pkcs11 = "0.3"
```

## Requirements

### Runtime

- `libopencie-pkcs11` **1.3.0 or newer** installed on the target system. Install from the upstream [releases](https://github.com/M0Rf30/opencie-pkcs11/releases) or build from source with [Meson](https://github.com/M0Rf30/opencie-pkcs11#building). Earlier versions do not export `cie_read_dgs_can` and do not define `CIE_ERR_WRONG_CAN`: `build.rs` refuses to build against a header that lacks them. Versions before 1.3.0 also differ in the return values of `cie_is_enabled`, `cie_get_certificate` and `cie_verify` that the wrappers rely on.

### Build

- A working `clang` toolchain (required by `bindgen`).
  - Debian/Ubuntu: `apt-get install libclang-dev`
  - Fedora/RHEL: `dnf install clang-devel`
  - macOS: `xcode-select --install`
  - Windows: install LLVM from <https://releases.llvm.org/>
- A checkout of the upstream C library so `build.rs` can run `bindgen` against its public headers.
  - Default location: a sibling directory `../opencie-pkcs11`.
  - Override with `OPENCIE_PKCS11_DIR=/path/to/opencie-pkcs11`.

`build.rs` does not vendor the C headers; only public headers under `include/opencie/` and `shared/src/pkcs11/pkcs11.h` are consumed.

## Usage

### PKCS#11 standard operations

```rust
use opencie_pkcs11::{ffi, pkcs11};

fn main() -> Result<(), pkcs11::Error> {
    pkcs11::initialize()?;

    let slots = pkcs11::get_slot_list(true)?;
    let session = pkcs11::open_session(
        slots[0],
        ffi::CKF_SERIAL_SESSION | ffi::CKF_RW_SESSION,
    )?;
    pkcs11::login(session, ffi::CKU_USER, "12345678")?;

    // ... cryptographic operations ...

    pkcs11::logout(session)?;
    pkcs11::close_session(session)?;
    pkcs11::finalize()
}
```

### CIE enrolment, PDF signing, verification

```rust
use opencie_pkcs11::cie;

fn main() -> Result<(), opencie_pkcs11::pkcs11::Error> {
    let pan = "1234567890123";
    let pin = "12345678";

    if !cie::is_enabled(pan) {
        cie::enable(pan, pin)?;
    }

    // PNG bytes drawn into the signature widget; pass None to omit the stamp.
    let stamp: Option<&[u8]> = None;

    cie::sign(
        "input.pdf",
        "PDF",
        pin,
        pan,
        0,                    // page (0-based)
        0.10, 0.10,           // x (left), y (bottom) as fractions of the crop box
        0.40, 0.10,           // width, height as fractions (0.0 hides the widget)
        stamp,
        "signed.pdf",
    )?;

    // Number of signatures found (valid or not); inspect each one below.
    let count = cie::verify("signed.pdf", None, 0, None)?;
    for i in 0..count {
        let info = cie::get_verify_info(i)?;
        println!("{}. {} {} — valid: {}", i, info.name, info.surname, info.is_sign_valid);
    }

    cie::extract_p7m("document.pdf.p7m", "document.pdf")?;
    Ok(())
}
```

### Certificate, timestamp

```rust
use opencie_pkcs11::cie;

// DER X.509 certificate of a paired card (cache written by `cie::enable`, or
// the CIE ID pairing cache with the card on the reader). The buffer allocated
// by the library is copied and released with `cie_free` internally.
let der = cie::get_certificate("1234567890123")?;

// Standalone RFC 3161 timestamp (SHA-256), no card needed.
cie::timestamp("report.pdf", "https://tsa.example.org/tsr", None, None, "report.pdf.tst")?;
# Ok::<(), opencie_pkcs11::pkcs11::Error>(())
```

### Chip data groups (DG1 MRZ + DG2 photo)

`read_dgs_can` authenticates with ICAO 9303 PACE using the 6-digit CAN printed on the card; no PIN is used or consumed. `read_dgs` is the PIN-based fallback.

```rust
use opencie_pkcs11::cie::{self, CanFailure};

let data = match cie::read_dgs_can("123456") {
    Ok(d) => d,
    Err(e) => match cie::can_failure(e) {
        // Wrong CAN: ask the user again, never retry with the same one.
        CanFailure::WrongCan => return Err(e),
        // Reader cannot send extended-length APDUs (e.g. ACR122U): use the PIN.
        CanFailure::ReaderLacksExtendedLength => cie::read_dgs("12345678")?,
        _ => return Err(e),
    },
};
println!("DG1: {} bytes, photo: {} bytes (PNG)", data.mrz.len(), data.photo_png.len());
# Ok::<(), opencie_pkcs11::pkcs11::Error>(())
```

A CAN that is not exactly six ASCII digits fails with `CKR_ARGUMENTS_BAD` before reaching the reader. `cie::last_error()` reports `ErrorKind::WrongCan` (`CKR_PIN_INCORRECT`), `ErrorKind::InsNotSupported` (`CKR_DEVICE_ERROR`) or `ErrorKind::UnsupportedCard` (`CKR_FUNCTION_NOT_SUPPORTED`) for the three failure modes.

### Reader management

```rust
use opencie_pkcs11::cie;

let initial = cie::reader_count();
println!("readers connected: {}", initial);
println!("first reader: {:?}", cie::reader_name());

// Block until the reader count changes (e.g. card inserted/removed).
let new_count = cie::reader_watch(initial);
println!("reader count is now {}", new_count);
```

### DigestInfo helper for raw RSA signing

Computed in Rust: the C `make_digest_info` is declared in `cie_ext.h` but is not exported by the Linux builds of `libopencie-pkcs11` (1.2.3 and 1.3.0), so it is not called. Unknown NIDs fail with `CKR_MECHANISM_INVALID` and digests whose length does not match the algorithm with `CKR_DATA_LEN_RANGE`.

```rust
use opencie_pkcs11::cie;

const NID_SHA256: i32 = 672;

let digest = [0u8; 32]; // 32-byte SHA-256 output
let der = cie::make_digest_info(NID_SHA256, &digest)?;
// Feed `der` into a raw RSA signing operation.
# Ok::<(), opencie_pkcs11::pkcs11::Error>(())
```

## Modules

- **`ffi`** — raw PKCS#11 bindings (generated by `bindgen`).
- **`cie_ffi`** — raw CIE extension bindings (generated by `bindgen`).
- **`pkcs11`** — safe wrappers around the standard PKCS#11 surface.
- **`cie`** — safe wrappers around the CIE extensions.

## Error handling

All fallible operations return `Result<T, pkcs11::Error>`, where `Error` wraps a `CK_RV` value:

```rust
use opencie_pkcs11::pkcs11::{self, Error};

match pkcs11::initialize() {
    Ok(()) => println!("initialized"),
    Err(Error(code)) => eprintln!("PKCS#11 error 0x{:08x}", code),
}
```

`CK_RV` is a C `unsigned long` (32-bit on Windows, 64-bit on LP64 Unix); `Error` wraps it unchanged. Arguments with an interior NUL byte (or a buffer longer than `i32::MAX`) fail with `CKR_ARGUMENTS_BAD`.

`cie_verify` returns the signature count and the error code in the same `CK_RV`. `cie::verify` treats a return value that differs from `cie_get_sign_count()` as an error (`CIE_SIGN_ERROR_*` values from `0x84000000`, negative statuses cast to `CK_RV`, or small `CKR_*` codes), as documented in `cie_ext.h`. `cie::get_sign_count` accepts values up to `i32::MAX`.

`cie::last_error()` returns the `ErrorKind` of the last failed call on the calling thread. `ErrorKind` is `#[non_exhaustive]`; it includes `UnsupportedCard` (10) and `WrongCan` (11).

## Callback support

The C library calls the progress and completion callbacks unconditionally, so passing `NULL` crashes it. The safe wrappers always install internal callbacks; progress can be observed with `cie::with_progress`:

```rust
use opencie_pkcs11::cie;

let mut log = |percent: i32, message: &str| eprintln!("{percent:>3}% {message}");
cie::with_progress(&mut log, || cie::change_pin("12345678", "87654321"))?;
# Ok::<(), opencie_pkcs11::pkcs11::Error>(())
```

Completion callbacks are not exposed (the wrappers return the final result). The raw `cie_ffi` module provides the typedefs for callers that need them; remember they must never be `NULL`.

## Changelog

### 0.4.0

- Target `libopencie-pkcs11` 1.3.0 (minimum version raised from 1.0.15). `build.rs` rejects older headers.
- Added `cie::read_dgs_can` (PACE with the 6-digit CAN), `cie::read_dgs` (PIN fallback), `cie::can_failure` / `cie::classify_can_failure`, `cie::get_certificate` (buffer released with `cie_free`) and `cie::timestamp`.
- Added `ErrorKind::UnsupportedCard` (10) and `ErrorKind::WrongCan` (11), and made `ErrorKind` `#[non_exhaustive]`. **Breaking** for exhaustive matches.
- Fixed: the wrappers passed `NULL` progress/completion callbacks, which the library invokes unconditionally (crash). Added `cie::with_progress`.
- Fixed: `cie::verify` / `cie::get_sign_count` classified results with a `0x1000` threshold; small error codes were reported as signature counts. `cie::verify` now compares against `cie_get_sign_count()`.
- Fixed: `cie::reader_name` returned a one-character name (the C function returns 1/0, not a length).
- Fixed: `cie::make_digest_info` is computed in Rust (the C symbol is not exported by the Linux builds) and rejects unknown NIDs / mismatching digest lengths instead of returning garbage; the error code for failures was `0x60` (`CKR_KEY_HANDLE_INVALID`), now `CKR_MECHANISM_INVALID` / `CKR_DATA_LEN_RANGE`.
- Fixed: interior NUL bytes were reported as code `1` (`CKR_CANCEL`), and silently dropped for the proxy arguments of `cie::verify`; they now fail with `CKR_ARGUMENTS_BAD`.
- Fixed: `cie::sign` no longer truncates a stamp image longer than `i32::MAX` bytes.
- Docs: `cie::sign` position/size arguments are fractions of the crop box (not points); `cie::is_enabled` is true only when a certificate cache exists (a card that is merely inserted no longer counts).

### 0.3.1

- Documented that `cie::is_enabled` also reports cards paired only through the
  official IPZS CIE ID app as enabled when inserted (upstream 1.0.15+
  behaviour; see [opencie-pkcs11#25](https://github.com/M0Rf30/opencie-pkcs11/issues/25)).
- Raised the minimum supported `libopencie-pkcs11` version to 1.0.15.

### 0.2.0

- Updated `cie::sign` to match the current `cie_ext.h`: the trailing `image_path: Option<&str>` parameter is replaced with `image_data: Option<&[u8]>`. **Breaking.**
- Removed the dead `sign` module and `sign_ffi` bindings: the C++ Sign SDK (`cie_sign_*` symbols) is no longer exported from `libopencie-pkcs11`.
- Added wrappers for `cie_get_verify_info`, `cie_reader_count`, `cie_reader_watch`, `cie_reader_name`, and `make_digest_info`.
- `build.rs` honours `OPENCIE_PKCS11_DIR` for non-default checkout locations.
